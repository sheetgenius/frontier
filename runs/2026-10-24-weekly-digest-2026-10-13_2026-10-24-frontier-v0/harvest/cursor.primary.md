## 1. Cloud agents can deliver a shareable canvas instead of a transcript-only result

- **Receipt:** https://cursor.com/changelog/cloud-agent-canvases-and-environments, https://cursor.com/docs/agent/tools/canvas
- **Half:** capability | **Confidence:** high

**What changed.** Cursor's dated launch makes interactive canvases an output of cloud agents. ## 2. The beta Environments API makes cloud setup scriptable, with replacement semantics and conflicting repo caps

- **Date:** 2026-10-16; CLI follow-up 2026-10-22
- **Channel:** `preview-or-beta`
- **Ancestry evidence:** Official 2026-10-16 launch explicitly labels the API beta. Current endpoint reference read 2026-10-24T09:42:48Z; CLI v2026.10.22 notes document the corresponding update command. No live API mutation was attempted.
- **Receipt:** https://cursor.com/changelog/cloud-agent-canvases-and-environments, https://cursor.com/docs/cloud-agent/api/endpoints#environments, https://cursor.com/docs/cli/changelog#oct-22-2026
- **Half:** both | **Confidence:** high

**What changed.** The API exposes creation, listing, configuration, history and builds for personal and team environments. A PATCH replaces the entire `environmentJson`; replacing `repos` requires sending that configuration too. Build settings must be changed separately. Zero- and one-repository environments cannot change their repository set. The launch says up to 300 repositories, while the current create-endpoint reference says 500. Its advertised fivefold loading improvement has no reproduced method here. The default CLI's release notes add `agent env deploy --env <public-id>`, preserving the environment's identity and rejecting supplied name/repository mismatches.

**Operator consequence.** Replace dashboard setup glue with a reviewed environment definition, but read before writing and retain the complete intended repository list. Follow pagination until the cursor is absent; the docs warn access checks and concurrent updates can yield partial or repeated results. Validate the cap on the actual endpoint before designing a 500-repository deployment. Automation removes setup clicks while increasing the importance of configuration review and rollback state.

## 4. Linux workers expose a live editor workspace only after a separate opt-in

- **Date:** 2026-10-20 notes; 2026-10-22 artifact
- **Channel:** `tagged-release`
- **Ancestry evidence:** Agents Window 3.26 notes and current self-hosted guide; static `worker-cursor-server.ts` resolver in `1375.index.js` returns supported only for explicit enablement on Linux. Darwin artifact inspection proves its guard, not Linux runtime enforcement.
- **Receipt:** https://cursor.com/docs/release-notes/agents-window#oct-20-2026, https://cursor.com/docs/cloud-agent/self-hosted#live-workspace, https://downloads.cursor.com/lab/2026.10.22-27dcf5f/darwin/arm64/agent-cli-package.tar.gz
- **Half:** both | **Confidence:** high

**What changed.** `--connect-workspace` lets the desktop app open a self-hosted Linux agent's files, terminal and forwarded ports. The guide requires Cursor 3.25 or later and a signature-verified matching server build downloaded from `cursor.blob.core.windows.net`. It runs on localhost and transports workspace traffic over the worker's outbound connection. This is separate from pixels or input control. **Operator consequence.** Treat enabling this flag as granting a terminal under the worker identity. Audit VM sharing and workspace tasks before opening an untrusted checkout. The feature can remove separate SSH setup for inspecting an agent's work, but a lack of inbound ports does not make the terminal read-only or restrict it to a reviewer role.
