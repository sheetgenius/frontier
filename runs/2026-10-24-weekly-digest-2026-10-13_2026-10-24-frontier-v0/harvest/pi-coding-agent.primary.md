## 4. Codemode cancellation is released with FIFO admission and a wait of at most 60 seconds

- **Date:** 2026-10-21
- **Channel:** `tagged-release`
- **Ancestry evidence:** `3daa20280f6a7c7cbe0935680c9a38fdc3863005` first reaches v1.3.0; FIFO admission `885a564b3b22dc6eefd55a78a8f6bb757ddfbc69` first reaches v1.4.0. Both are ancestors of the stable tag.
- **Receipt:** [Bun cancellation and admission](https://github.com/earendil-works/pi/commit/3daa20280f6a7c7cbe0935680c9a38fdc3863005), [queue change](https://github.com/earendil-works/pi/commit/885a564b3b22dc6eefd55a78a8f6bb757ddfbc69), [v1.4 execution code](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/src/extensions/codemode/execute.ts).
- **Half:** both | **Confidence:** high

**What changed.** The CLI's script call can return after cancellation or deadline even when a Bun worker is inside a non-interruptible built-in. Such a worker still occupies its slot until it actually exits. The default is two live workers across sessions in the process; `PI_CODEMODE_MAX_WORKERS` can override it. At saturation, 1.4 waits FIFO for up to 60 seconds rather than immediately failing. Queue time counts against a script's own timeout. The pending-waiter array has no explicit length cap; this bounds waiting time and live workers, not pending-request memory. Source review covered admission, reservation transfer, timeout and actual worker-exit release, not just the changelog.

**Operator consequence.** Upgrade hosts running concurrent or interruptible scripts to 1.4.0. Size concurrency against process memory and queue latency, and retain external containment for hostile work. A returned cancellation is not proof the worker or an already dispatched side effect stopped. This removes some homegrown admission control, but it does not fix codemode-only enforcement or create separate approval hooks for classifier/image calls.

## 8. Durable 1.4 can hibernate between phases, with a one-way SQLite upgrade

- **Date:** 2026-10-21
- **Channel:** `tagged-release`
- **Ancestry evidence:** durable sleeps `f75b3240abc354bd1a666748e9101220554f5be2` and required document checkpoint predicates `5c1736f82d201d09664642ab0d88147da94b450e` are absent from v1.3.0 and present in v1.4.0. Storage migrations, scheduler behavior and the tagged README were read together.
- **Receipt:** [breaking changes](https://github.com/earendil-works/pi/blob/v1.4.0/packages/durable/CHANGELOG.md), [sleep and host contract](https://github.com/earendil-works/pi/blob/v1.4.0/packages/durable/README.md#L139-L220), [SQLite migration](https://github.com/earendil-works/pi/blob/v1.4.0/packages/durable/src/storage/sqlite/migrations.ts), [Cloudflare integration update](https://developers.cloudflare.com/changelog/post/2026-10-22-pi-harness-pi-1-4/).
- **Half:** both | **Confidence:** high

**What changed.** `runtime.sleep()` is removed. `sleepUntil()` ends a phase with a durable checkpoint and a `sleeping` task, allowing retry backoff, deferred polls and scheduled work to release their invocation. `wake()`/`onWake` tell a host whether work is active or the earliest time it must restart. This makes host alarms a real part of correctness: the host must arrange a durable wake and reopen/resume the harness; an in-memory timer alone cannot wake a dead process. SQLite automatically migrates to schema version 2, which 1.3.0 and earlier cannot open. JSONL needs no migration, but older code cannot resume the new sleeping task state. Every `defineDoc`/`defineDocFamily` must supply `checkpointWhen`; `() => false` deliberately retains delta-only behavior. Version 1.3 had already added SQLite namespacing and coordination for shared Durable Object storage, corrected the leading system baseline after compaction, and reduced image base64 memory pressure.

**Operator consequence.** Back up persistent state and plan rollback before any 1.4 process opens the database. Split work after a wait into a new phase, update exhaustive state handlers and fakes, and verify that alarms survive a process dying around a commit. The gain is substantive: the host need not keep an invocation alive merely to wait. The scarce engineering attention moves to wake ownership, storage migration and replay-safe external effects, not another chat-loop wrapper. The dated Cloudflare announcement describes Agents SDK 0.30.0 adopting this host contract; it is not evidence that every hosted Pi front end has upgraded.

**What changed.** A task interrupted five times without committing new state is parked with `restart_limit`; it no longer counts as active work and stays parked at the current limit; `retryTask()` clears its restart count, and raising `restartLimit` can also make it runnable. IndexedDB adds a browser storage backend, and function-valued models/settings let a host replace configuration without reopening the harness.

**Operator consequence.** Surface parked work and the retry action in the host UI, and distinguish a stopped crash loop from a completed job. Hosts can remove some restart and tracing scaffolding, but still own failure policy and credential handling. Check the host's override: released Pi Pocket 0.21.0 pins Durable 1.4.0 yet explicitly sets `restartLimit: Infinity`, citing long phases that may be killed repeatedly. Upgrading the library alone therefore does not establish the default guard in a product. IndexedDB is a useful embedding primitive, not a complete browser execution or isolation product.

JSONL compatibility in a UI is not durable task recovery. Compaction, system baselines, startup handlers and removed SDK types all require consumer-specific checks.
- **Features operators must still supply:** Pi's [security contract](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/security.md) still puts containment outside the CLI and lets extensions run with process authority. Native MCP is no longer an example of an omitted feature; custom approvals, subagent workflows and hosted Durable alarm/recovery policy remain extension or host work. The ecosystem supplies choices, not one centrally enforced policy.
- **Wrapping Pi versus borrowing its extension contract:** pi-web and pi-gui demonstrate embedding, while Oh My Pi demonstrates a fork with distinct policy and maintenance obligations. The [adapter's removal of its own script engine](https://github.com/nicobailon/pi-mcp-adapter/blob/v6.0.0/CHANGELOG.md) is direct evidence of upstream capability replacing handcrafted code. The cost is tracking versioned contracts and their security consequences, especially for hosts that lag stable.
- **Making work easier to inspect and control:** [Durable reports, task graphs and telemetry](https://github.com/earendil-works/pi/blob/v1.4.0/packages/durable/README.md) improve visibility; [adapter nested-call hooks](https://github.com/nicobailon/pi-mcp-adapter/blob/v6.0.0/CHANGELOG.md) expose real tool identity. Neither guarantees provenance-safe summaries, exactly-once external effects, or the same control policy in every front end.
