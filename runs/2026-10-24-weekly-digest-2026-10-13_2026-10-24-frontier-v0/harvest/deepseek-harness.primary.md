## 4. SDK session resume and optional PTC memory reduce restart work without restoring running processes

- **Date:** 2026-10-14
- **Channel:** `preview-or-beta`
- **Ancestry evidence:** SDK resume `0bec9479aea3651479ea52a7569e2717e6c02d76` and persistent Node PTC `4fb14dcac6785bc214299b0327f46822b8901427` first appear in alpha.3, then rc.1 through rc.3. Official Python rc.2 distributions were published on 2026-10-17.
- **Receipt:** [TypeScript SDK](https://github.com/deepseek-ai/deepseek-harness/blob/1f81c047fc48fa190a683e469daa699857e9afe8/packages/sdk/client/README.md), [Python SDK](https://github.com/deepseek-ai/deepseek-harness/blob/1f81c047fc48fa190a683e469daa699857e9afe8/python/sdk/README.md), [Node PTC](https://github.com/deepseek-ai/deepseek-harness/blob/1f81c047fc48fa190a683e469daa699857e9afe8/packages/ptc-runtime/ptc-runtime-node/README.md), [Python distribution](https://pypi.org/pypi/deepseek-harness-sdk/0.2.1rc2/json).
- **Half:** capability | **Confidence:** high

**What changed.** SDK callers gain `resumeSession`/`resume_session`, retaining the saved session ID, history and working directory, repairing an interrupted final turn without sending a new prompt. Missing, incompatible or occupied sessions fail instead of silently becoming new sessions. Node PTC adds optional `persistent-in-memory` execution to reuse variables, functions and modules across calls; `per-call` remains the default. Persistent memory is per agent and best effort: restart, disposal, cancellation, timeout and execution failure can clear it, and a resumed or forked session starts without that memory.

**Operator consequence.** Replace custom conversation-reconstruction glue with the resume API, but retain explicit checkpoints for external side effects and long-running processes. Reusing a session is not crash recovery of a shell, browser or tool call. The tagged [terminal contract](https://github.com/deepseek-ai/deepseek-harness/blob/1f81c047fc48fa190a683e469daa699857e9afe8/packages/api/terminal-controller/README.md) likewise distinguishes reconnecting to a live Host process from restoring one after Host disposal. The durable primitive is session history; the attention bottleneck moves to checking which external actions actually completed.
