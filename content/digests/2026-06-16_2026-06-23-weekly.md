# Protected on Paper

Claude Code 2.1.178 shipped a five-level cap on nested subagents. It did not
apply to foreground spawns. Until
[2.1.181](https://code.claude.com/docs/en/changelog), a foreground subagent
could spawn unbounded nested chains, and the fix says so in one line: they
"now respect the same 5-level depth limit as background subagents."

The same window disclosed a second one. The `Agent(type)` deny rules and
`Agent(x,y)` allowed-type lists, written in the argument-aware permission
grammar that shipped last window, were
[not enforced](https://code.claude.com/docs/en/changelog) for named subagent
spawns until 2.1.186. An operator who wrote either rule the day it was
announced was protected by a sentence in the docs.

That is one of three places a control can live without being on your machine.
It can be written down and not enforced. It can be merged to a branch you do
not run. Or it can sit one release newer than yours. This window found
protections in all three.

## A rule binds when something refuses

Credit where it is due: Claude Code disclosed both gaps in its own changelog.
The fixes are the good news. The lesson
travels past Claude Code: a permission feature is not a permission boundary
until something refuses the disallowed action, and the only way to know is to
test it.

The same release train tightened what did bind. 2.1.183 lists the
[destructive commands](https://code.claude.com/docs/en/changelog) the
auto-mode classifier refuses unless the operator asked to discard the work,
`git reset --hard`, `git clean -fd` and `terraform destroy` among them, and
fixes scheduled-task and webhook triggers whose inputs could slip an action
past classification. Then 2.1.187
[[q:claudecodelog-sandbox-credentials]], and made remote MCP calls abort after
five minutes instead of hanging. A sandbox that could read the secrets of the
environment it sandboxed was not much of a sandbox.

Codex shipped the cleanest example of the shape. CLI 0.142.0 made command and
network approvals
[environment-scoped](https://github.com/openai/codex/pull/28899): an approval
granted in one execution environment no longer carries to another, Codex
"denies when active-call attribution is ambiguous", and it fails closed if an
environment's proxy cannot be prepared. The same release lets a rollout token
budget [abort the turn](https://github.com/openai/codex/pull/28746) when it
runs out. That is a hard cap on spend, with soft timing: it lands at the next
accounting boundary, not mid-call.

Tagged, stable, and failing closed. That is what protection looks like when it
arrives.

## The fix was merged, and the binary did not have it

Most of the window's security work never got that far.

**OpenHands** is still on
[1.8.0](https://github.com/OpenHands/OpenHands/releases/tag/1.8.0), from 10
June. Two windows of enterprise and security work sit on main in no tag,
including the
[postcss XSS fix, CVE-2026-41305](https://github.com/OpenHands/OpenHands/pull/14770),
and a fix that stops a `PluginSpec.source` with an embedded git token from being
[written to the database in plaintext](https://github.com/OpenHands/OpenHands/pull/14795).
New writes are redacted; rotate any token that was already embedded in a repo
URL.

**Gemini CLI** left its skill
[path-traversal fix](https://github.com/google-gemini/gemini-cli/commit/bca5667fc)
in `v0.48.0-preview.0` for a second week. On stable `v0.47.0`, a malicious
`.skill` package can still write outside the skills directory. In the same
cycle, stable received a built-in
[`antigravity-support` skill](https://github.com/google-gemini/gemini-cli/pull/27765)
that hands users a `curl ... | bash` install of a successor CLI, and the
"Antigravity is coming to town" banner
[lost its five-show cap](https://github.com/google-gemini/gemini-cli/pull/27676).
A security fix and a growth funnel went through the same release gate. Only
one came out the stable side.

**Hermes Agent** tagged
[v0.17.0](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.6.19)
on 19 June with last window's fail-closed wave: the
[cp-into-`~/.ssh` gate](https://github.com/NousResearch/hermes-agent/commit/da28d5d11)
a maintainer had called "theater", the `/api/status` host-path leak fix and
the fail-closed policy adapters. Two days later a new wave landed on main
instead. It
[rejects MCP entries](https://github.com/NousResearch/hermes-agent/commit/7726ce304)
that write shell payloads into `authorized_keys`, cron or sudoers, enforces an
IOC blocklist at save and spawn time, raises the API-key entropy floor from 8
to 16, and adds a
[startup audit](https://github.com/NousResearch/hermes-agent/commit/f45ace931)
that warns when a gateway runs as root or serves an unauthenticated API. The
commits say it answers an exploitation campaign in the wild. That claim rests
on the project's own narrative, a Reddit thread and a self-named instance; the
mechanism and the fixes are verified. Either way, v0.17.0 does not contain it.

**Paperclip** ran the pattern in reverse.
[v2026.618.0](https://github.com/paperclipai/paperclip/releases/tag/v2026.618.0)
(18 June) finally tags last window's master-only tenant cluster: the
[instance-admin deprivileging](https://github.com/paperclipai/paperclip/pull/7525)
for cloud tenants, every one of whom had been an instance admin on a shared
pool; per-company JWT signing keys; plugin tenant isolation; HTTP-log credential
redaction; and a
[review fix](https://github.com/paperclipai/paperclip/pull/5839) for a comment
reading "NOT APPROVED" that could auto-complete an issue. Then its newest
controls went straight back onto master.

## Who the agent is, and what it may spend

The rest of the window's authority work was about identity and money, and it
pulled in both directions.

OpenHands decoupled
[API-key authentication](https://github.com/OpenHands/OpenHands/pull/14867)
from Keycloak sessions: "API-key authentication performs zero Keycloak
round-trips." Headless clients stop hitting opaque 401s. The price is a changed
revocation contract. Killing a user's IdP session no longer kills their machine
keys, so revocation now happens at the key store. A companion
[secret enricher](https://github.com/OpenHands/OpenHands/pull/14697) injects a
user's linked OAuth token into the sandbox from any conversation start path,
and OpenHands moved sandbox images onto a
[runtime-api control plane](https://github.com/OpenHands/OpenHands/pull/14849)
that makes per-tenant images possible. The credential now follows the user into
whatever runtime they start. All of it is on main.

Hermes came at identity from the other end, with a
[managed `/etc/hermes` scope](https://github.com/NousResearch/hermes-agent/pull/49098):
root-owned, user-immutable config and secrets that win per key over a user's
own files. It is Hermes's first OS-backed policy pin.

On money, Paperclip's master adds
[preflight budget caps](https://github.com/paperclipai/paperclip/pull/8347)
that cancel queued work before an adapter starts, and a
[watchdog](https://github.com/paperclipai/paperclip/pull/8339) whose recovery
actors cannot touch approvals. OpenHands went the other way and
[reverted](https://github.com/OpenHands/OpenHands/pull/14877) last window's
per-org concurrency limits outright. Hermes removed the default wall-clock
timeout on subagents in the same week it shipped fire-and-forget background
fan-out. And OpenClaw stable
[v2026.6.9](https://github.com/openclaw/openclaw/releases/tag/v2026.6.9) began
approving Codex plugins automatically: one gate opened while most of the
watchlist was closing them.

[moved consumer Gemini CLI users](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/)
to Antigravity CLI. The product account put it flatly:

access, and the open-source repository continued. A maintainer called the day

## What became possible

The window was not only gaps.

OpenClaw's
[WCAG 2.1 AA pass](https://github.com/openclaw/openclaw/releases/tag/v2026.6.8)
reached stable v2026.6.8 after a week in beta: dark-mode contrast lifted to
4.5 to 1, real keyboard focus rings, a 12-pixel font floor across 136 elements.
A low-vision or keyboard-only operator can now reach the authority surfaces on
the default channel. That is the precondition for anyone using the controls the
rest of this issue argues about.

Anthropic launched Claude Tag, which puts Claude in Slack channels as a
delegate. Its creator marked the launch with a number:
[[q:bcherny-65-percent-tag]]. It is a vendor's claim about its own codebase,
with no published method, and still the most specific statement anyone made
this window about how much work agents already do. Further down the same
thread he described the security model, including that
[[q:bcherny-tag-security-layers]]. That is a vendor's claim about a product we
did not test, and exactly the kind of sentence this issue says to check. The
nearest receipt is a different surface: Claude Code's `sandbox.credentials`,
shipped in the CLI that same day.

At OpenHands, Xingyao Wang started from the bottleneck behind all of it: agents
open pull requests in minutes, and on codebases that matter those PRs wait days
for a human. His team built a verification stack, and
[[q:xingyaow-verification-stack]]. It is his number, not one we checked, and
it is the constructive half of this issue's argument: a check that runs before
the human looks, not a rule that waits in the docs.

Graham Neubig opened a harness-versus-harness evaluation by noting that most
benchmarks hold either the model or the harness fixed, when in practice
[[q:gneubig-harness-plus-llm]] His results: [[q:gneubig-benchmark-trends]],
and the ranking flipped when the model changed. If the winning harness depends
on the model you point at it, the harness is a setting you tune, not a brand
you pick once.

The cost of all this building showed up too. The night heypi 0.2.0 beta
shipped, its maintainer wrote [[q:hunvreus-burnout]].

## Breaking changes

**Paperclip v2026.618.0** purges stale instance-admin rows for cloud tenants.
Create a separate admin identity before you upgrade a shared pool.

**OpenHands main** drops the per-org concurrency columns in migration 124. The
429-based quota some operators were waiting for will not arrive in that form.

**[Flue 1.0.0-beta.3](https://github.com/withastro/flue/blob/v1.0.0-beta.3/CHANGELOG.md)** removes `flue logs` in favor of typed SDK run APIs, makes
workflow runs private over HTTP unless the workflow exports `runs` middleware,
and rebuilds workflows around Actions.

## Three addresses, none of them yours

Nobody lied this window. The permission grammar exists, the depth cap exists,
the fixes exist, and an operator running the tagged binary had none of them.
The work is being done faster than the release and enforcement plumbing around
it can carry it to the machine that runs the agent.

Merged is a place. Shipped is a place. Neither one is your machine.
