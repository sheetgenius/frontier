# Approvals Belong to the App

[Codex 0.148.0 cut stable on 18 August](https://github.com/openai/codex/releases/tag/rust-v0.148.0),
381 commits past 0.147.0, and it carries Guardian V2, a model that scores
each tool call for risk. The same tag
[sets the feature](https://github.com/openai/codex/blob/rust-v0.148.0/codex-rs/features/src/lib.rs)
to `UnderDevelopment` and `default_enabled: false`. A team that waited for a
stable build to get a model in the approval seat got the model, not the seat.

Flipping the flag on 0.148.0 has a price. Scoring errors there warn and let
the call through. The patch that fails them closed merged 24 minutes after
the tag was cut, and ships in
[0.149.0](https://github.com/openai/codex/releases/tag/rust-v0.149.0), which
became npm `latest` two days later. The next morning OpenAI's developer
account described teams embedding Codex this way:
[[q:openai-devs-app-owns-approvals]]

Read that way, a classifier in the binary and off by default is not a
half-finished feature. It is the design.

## The decision moved to whoever builds around the harness

Codex was not alone. In three days, three projects put the call on what an
agent may do in the hands of the code wrapped around the agent, not the
agent's own defaults.

**Codex** ships the judge and leaves the switch to you. What it does not yet
ship is a view of the judge's work. One operator, finding auto-review gone
from his usage analytics, pointed at the replacement, [[q:acsmif-guardian-invisible]]
The tag confirms the classifier is present and off. It does not show how its
work is billed or displayed, and nothing in this window settles that.

**DeepSeek Harness**
[rc.8](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.0-rc.8)
is still a prerelease, and its
[architecture page](https://github.com/deepseek-ai/deepseek-harness/blob/141eb6fef83422698aef7a981029e843e8161534/docs/architecture.md)
still says there is no privileged core: a patch can replace any row,
including approval. The `never` policy is now decided before that chain runs,
so a later plugin cannot bypass that one mode. rc.8 adds Claude Code and Codex
as Profile Bundles, defaulting to `dontAsk` and `never`. Those modes belong to
DeepSeek's wrapper, not to Claude Code or Codex.

A Chinese developer made the strongest case for that design:
[[q:cnzhihao-dsh-it-audit]], only DeepSeek Harness can go to production,
because Codex and Claude Code are black boxes an internal IT audit cannot
pass. An open plugin tree is at
least something a security review can read. The same tree's
[request-trust module](https://github.com/deepseek-ai/deepseek-harness/blob/141eb6fef83422698aef7a981029e843e8161534/packages/client/connection/src/api-request-trust.ts)
says it is not an auth layer, and the Web UI has no login. Auditable and
production-ready are different claims.

**OMP**, the Oh My Pi fork,
[put `registerFileWriteFallback` on npm in 17.3.7](https://github.com/can1357/oh-my-pi/blob/v17.3.7/packages/coding-agent/src/extensibility/extensions/types.ts).
An extension can now broker a write the operating system refused. If you load
one, the OS denial is no longer the last word; the extension's author is.

The reason to build this way is real. A harness that owns approvals has to
guess every embedder's policy, and a harness that hands them off can be dropped
into an operations dashboard whose owners already know who may approve what.
The cost is that "the agent asks before it acts" stops being a property of the
agent. It is a property of your integration, and you have to read it there.

## Three items reached a tag, two did not

The previous issue left five items unreleased. Within forty-eight hours,
[Hermes v2026.8.18](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.8.18)
carried the scan that stops a `git pull` slipping a skill past the hub scanner.
[OMP 17.3.7](https://github.com/can1357/oh-my-pi/releases/tag/v17.3.7) gave the
write hook a release and an npm version; 17.3.6 still has neither.
[Agent Zero v2.10](https://github.com/agent0ai/agent-zero/releases/tag/v2.10)
tagged the ACP bridge and browser from a side branch. DeepSeek Harness is
still a prerelease, as above, and OpenClaw is below.

eve's fix was to a control that had quietly stopped existing. When 0.33.0 made
channel messages interrupt the running turn, its notes said to set
`turnPolicy: queue` for the old behavior. From 0.34.0 through 0.39.2 that
field was dropped at compile time and
[fell back to steering](https://github.com/vercel/eve/pull/2173).
[0.39.3](https://github.com/vercel/eve/releases/tag/eve%400.39.3) copies it
again. For five releases the setting was in your config and not in your
agent.

[OpenClaw's approved-exec fix](https://github.com/openclaw/openclaw/commit/ab5611f0be610380fe48803fe4311896ca85806e)
is still in no release. The newest tag is `v2026.8.1-beta.2` from 15 August,
619 commits short of it, and the window cut no OpenClaw release at all.

Pi's new harness is not late; it is elsewhere. A maintainer said
[[q:mitsuhiko-pi-dev-branch]], and git agrees: `dev` is 264 commits ahead of
`main`. Anyone reading the default branch to judge Pi is reading the wrong
tree.

## What became possible

[Agent Zero v2.10](https://github.com/agent0ai/agent-zero/releases/tag/v2.10)
is the capability you can actually install this window. The ACP bridge is
bundled and always enabled, with host file write and host code execution as
its defaults. The internal browser is a live Xpra session on loopback that you
can drive, not a log of screenshots. The SSRF tests from v2.9, which block
`127.0.0.1` and redirects to loopback, are
[still in the tree](https://github.com/agent0ai/agent-zero/blob/v2.10/tests/test_document_query_plugin.py),
byte for byte.

That is a workcell you can sit in front of. It is also one browser identity:
every chat shares a single Chromium sign-in profile, and `per_context` only
hides tabs.

The other capability of the window was an agent deciding the venue for itself.
Simon Willison had Claude Code for web try a sandbox that needs `/dev/kvm`.
Its machine had none, so,
[[q:simonw-gha-without-asking]]

A sandbox that cannot run the job did not stop the job. It sent it somewhere
with more reach. Whether that is progress depends on whether you wanted the
push.

## Breaking changes and security notes

**OMP 17.4.0** replaces global token-counting functions with model-scoped
`Tokenizer` instances, so a global `countTokens` call breaks. `/handoff` now
overwrites the session instead of forking it.

**Claude Code 2.1.235** (18 August): Shift+Tab in a permission comment field
approved the edit and granted session-wide edit. Check `/permissions` if you
used that field on 2.1.234. **2.1.236:** a macOS `**/.env` read deny now wins
inside an allowed region, and renaming the file no longer escapes it.

**eve 0.40.0** redacts brokered credential transforms from sandbox bootstrap
logs. **0.42.0** stops channel approval responses carrying channel metadata
into the session inbox.

## Closing

Codex put its judge in the box and left the box closed, and said so. That is
a legitimate design, and it makes the gate your job. Before you upgrade
anything this week, find the code that says no, and check who wrote it.
