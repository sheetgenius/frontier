# Who's Allowed to Say Yes

Before 13 June, Hermes Agent would stop an agent writing to your SSH keys the
obvious way and wave it through the side door. A safety rule denied redirecting
output into `~/.ssh/authorized_keys`. It said nothing about copying a file
there. So `cp evil ~/.ssh/authorized_keys`, an implant and a foothold on the
operator's machine, sailed past a guardrail that existed on paper. The
[commit that closed it](https://github.com/NousResearch/hermes-agent/commit/da28d5d11)
called an unpaired write deny what it was: "theater."

The pressure behind the fortnight was depth. On 9 June Claude Code's creator
posted [[q:bcherny-nested-subagents]], and a reader did the arithmetic the
announcement skipped: [[q:crepesupreme-depth-five]], each layer multiplying
invocations and context. Another took on the launch's stated purpose, better
context management, and turned it around: [[q:edwin-nesting-launders-context]] OpenHands became a platform where the
[first person to log in owns the organization](https://github.com/OpenHands/OpenHands/pull/14752).
Paperclip began routing
[untrusted pull requests and comments](https://github.com/paperclipai/paperclip/pull/7530)
to agents that can be prompt-injected.

A per-action prompt does not scale to a five-deep delegation tree or a shared
tenant pool. So nine of ten providers spent the window deciding, in advance and
in code, who is allowed to say yes. The catch is that several of the sharpest
answers were merged and not released.

## Authority caught up with depth

Across provider after provider, a control that used to be a prompt, a default or
an honor-system check became enforced, inspectable state. It happened along
four fault lines.

**Recursion.** Claude Code agents can now
[spawn subagents that spawn subagents](https://code.claude.com/docs/en/changelog),
five levels deep. (Correction: foreground spawns did not respect that cap until
[2.1.181](https://code.claude.com/docs/en/changelog#2-1-181).) Real capability,
and at once a governance problem: a great-grandchild could request what the
top-level policy would block. A builder named the default he wanted the next
day: [[q:darshan-narrow-at-each-spawn]] What shipped is narrower than that
ask. The same line taught the auto-mode classifier to
evaluate a spawn before it launches, added a `Tool(param:value)` grammar so a
rule can match arguments (`Agent(model:opus)` blocks Opus subagents), and fixed
server-level MCP denials being silently ignored inside a subagent. It also
stopped a relayed `SendMessage` from a peer session carrying user authority.
Each of those carries the parent's limits down the tree. None makes a child's
scope shrink by default.

Hermes pushed from the other side with
[fire-and-forget background subagents](https://github.com/NousResearch/hermes-agent/commit/c66ecf0bc)
whose results re-enter the conversation as a new turn. The same week it removed
the default ten-minute worker timeout. Where Claude Code picked the depth,
Hermes's lead said the operator does: [[q:teknium-width-and-depth]], set in
`config.yaml` or the dashboard. The width half is in the commit, a
`delegation.max_async_children` cap that defaults to three; the depth half is
his word.

**Tenancy.** OpenHands spent the window becoming a tenant-provisioning system:
a default-organization bootstrap keyed to a database flag,
[per-org and per-user concurrency limits](https://github.com/OpenHands/OpenHands/pull/14168)
enforced with HTTP 429, and a
[BYOK gate](https://github.com/OpenHands/OpenHands/pull/14773) that locks an org
to a curated, proxy-served model set. It was also candid about a limit. Its
[hide-personal-workspaces flag](https://github.com/OpenHands/OpenHands/pull/14741)
is, in its own docs' words, "not an access-control boundary." Paperclip closed
a tenant privilege escalation (below), isolated
[plugin tables per tenant](https://github.com/paperclipai/paperclip/pull/5865),
and stopped HTTP error logs writing
[plaintext passwords and bearer tokens](https://github.com/paperclipai/paperclip/pull/8013)
to disk.

**Untrusted input.** As agents read code and messages they did not write,
providers drew the boundary around the input. Paperclip's
[deny-by-default "low-trust review" preset](https://github.com/paperclipai/paperclip/pull/7530)
gives an agent reviewing a hostile pull request narrower authority than usual
and quarantines its output from higher-trust context. Its maintainer put the
promise plainly: [[q:dotta-low-trust-wont-pwn-org]], with the condition in
parentheses that instances are sandboxed. Pi's
[project trust](https://github.com/earendil-works/pi/releases/tag/v0.79.0)
refuses a repo's local settings, instructions and packages until the operator
approves. Hermes stopped skills
[poisoning every connected memory store](https://github.com/NousResearch/hermes-agent/commit/c2c55c444)
and an agent-triggered skill delete from
[escaping its directory](https://github.com/NousResearch/hermes-agent/commit/2dbc3bd93),
a fix ported from an incident that did exactly that to another tool's user.
Gemini CLI fixed three path traversals at skill install (below). OpenClaw
moved the install decision itself to the operator, announcing that
[[q:openclaw-install-policy]] Switched on but unable to run, it fails
closed.

**Guardrails caught not holding.** The most telling commits were providers
finding their own controls hollow. OpenClaw's
[security boundary sweep](https://github.com/openclaw/openclaw/releases/tag/v2026.6.6)
made exec approvals "fail closed on timeout," so a pending dangerous command
that times out is denied. Paperclip found its review gate
[matched negated phrasings](https://github.com/paperclipai/paperclip/pull/5839):
a comment reading "NOT APPROVED" could auto-complete an issue, and the comment
and status change were not atomic. Agent Zero
[narrowed the trust set](https://github.com/agent0ai/agent-zero/commit/ca4efe6e6)
on its public Tailscale tunnel to the active origin. Codex made remote
controllers
[listable and revocable](https://github.com/openai/codex/releases/tag/rust-v0.137.0)
and bound approvals to an environment identity.

None is a headline feature. Together they are the field auditing the authority
it advertised against the authority it enforced.

## The fixes no tag carried

The awkward part is the channel. Hermes tagged v0.16.0 on 6 June and landed its
fail-closed wave on main a week later. Paperclip put its whole multi-tenant
cluster on master. OpenHands shipped one frontend CVE fix in 1.8.0 and left the
other, and its plaintext-token fix, on main. Gemini CLI's skill fix was in no
tag, stable or preview, when the window closed.

An operator on the newest release of all four was running without them. The difference between a merged fix and a tagged one is the
difference between being protected and believing you are.

## The market started to move

Underneath the authority work, the agent-CLI market repositioned, and one
practitioner named what that means for a stack: [[q:gthimmes-vendor-risk]]

Google began routing Gemini CLI users to another product. A
[transition banner](https://github.com/google-gemini/gemini-cli/commit/f40498db6),
cherry-picked into stable v0.45.2, was exempted from the usual five-times cap,
so "Antigravity is coming to town" shows every session it is active. A preview
build added
[migration commands and a built-in skill](https://github.com/google-gemini/gemini-cli/commit/452356027)
pointing to "Antigravity CLI," a separate agent CLI with its own binary,
installer domain and docs. The marketing is in stable; the tooling is a preview
away. It reads less like a feature than a managed succession.

OpenAI came at switching costs from the other side. Codex app 26.608 added
[Migrate-to-Codex flows](https://developers.openai.com/codex/changelog) that
import supported setup from Claude Code and Claude Cowork, including during
onboarding. Paperclip
[retired its "zero-human companies" tagline](https://github.com/paperclipai/paperclip/pull/7580)
for "the app people use to manage AI agents for work," and the fortnight's
engineering backs the new line: board visibility, an audited recovery action for
stuck agents, and the approval gates above. The autonomous company is being
repriced as human-in-the-loop operating software.

The counter-position shipped the same fortnight. Flue 1.0 Beta arrived
[[q:fredkschott-flue-1-0]], and an engineer was
[[q:elithrar-porting-to-flue]] on launch day. Whether that promise holds is not
yet known. That it is the pitch, in the fortnight Google began moving users off
an open CLI to a closed one, is the market answering itself.

## The model moved, and people noticed before the benchmarks did

On 9 June [Claude Fable 5](https://www.anthropic.com/news/claude-fable-5-mythos-5),
a "Mythos-class" model, reached Claude Code 2.1.170. Its maker's verdict was
the expected one: [[q:bcherny-fable-best-model]]. A vendor's claim about its own
model is worth what it cost to make.

What followed was worth more. Over the next week, unprompted, practitioners
reached for the same shape of description. One found that
[[q:bayeslord-intelligence-blackout]]. Another put it flatly:

<!--card:l1ad-fired-for-being-stupid-->

We ran no evaluation. What is observable is the reaction: a step change
registered as people describing going backwards, within days.

The speed is the operator consequence. Within days
[OpenClaw](https://github.com/openclaw/openclaw/releases) and
[Pi](https://github.com/earendil-works/pi/releases/tag/v0.79.1) supported it, Pi
with xhigh reasoning effort. If your allowlist pins model IDs, it went stale in
days. If it does not, your delegated trees changed capability without a release
note on your side. Claude Code shipped the lever for exactly this: an
[`enforceAvailableModels` setting](https://code.claude.com/docs/en/changelog) and
fixes in 2.1.175 and 2.1.176 that make an org's model allowlist bind even
against the default model and env-var overrides.

The same release line also added a
[`fallbackModel` chain](https://code.claude.com/docs/en/changelog) of up to three
models for when the primary is overloaded, which means a session can change
model mid-flight. On launch day plus one, a security researcher told another
user to check `/model`, because in his own session
[[q:wunderwuzzi-silent-downgrade]]. He caught it only after switching the
behavior off in `/config` so the session stops instead. His report does not
say what triggered the switch. It does say which witness not to trust: the
model's account of itself.

## Computer use grew up, and got metered

Codex app 26.609 added
[Developer mode for the browser](https://developers.openai.com/codex/changelog),
giving the agent "controlled" Chrome DevTools Protocol access. CDP can read
network traffic, run arbitrary JavaScript in the page, and drive the debugger:
a far larger surface than clicking and typing.

The same build added per-app access controls for computer use on Windows and
opened it to Enterprise users. On 16 June Codex
[made computer use available in the EEA, the UK and Switzerland](https://developers.openai.com/codex/changelog).
It also previewed Chronicle, an opt-in feature that builds the agent's memory
from recent screen context. Keep it off on confidential machines.

Here the capability and its governance lever arrived in the same build, not a
quarter apart.

## Access widened, too

Not everything was lockdown. OpenClaw shipped a measured
[WCAG 2.1 AA pass](https://github.com/openclaw/openclaw/pull/89822) on its
browser dashboard: muted text lifted above the 4.5-to-1 contrast floor it had
failed in dark mode, a real keyboard focus ring, and a 12-pixel font floor
across 136 elements. An agent harness treating low-vision and keyboard-only
users as engineering, not someday, is rare enough to note. It is a beta build.

On a stable release OpenClaw also
[stopped auto-selecting key-free web search providers](https://github.com/openclaw/openclaw/releases/tag/v2026.6.8),
giving up some zero-config convenience to make the user choose where their
queries go. Consent over default, pointed at the user instead of the agent.

Codex brought
[/goal, branch and worktree selection, and inline code review to the iPhone](https://developers.openai.com/codex/changelog).
Hermes shipped a
[native desktop app and a browser admin panel](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.6.5)
that take install to first message in seconds. The panel is a new authority
boundary, and its hardening is the unreleased wave above.

## Breaking changes and security notes

**OpenHands.** [CVE-2026-42342 in react-router](https://github.com/OpenHands/OpenHands/pull/14684)
is fixed in 1.8.0, uncredited under "Many UI bug fixes." The moderate XSS
[CVE-2026-41305 in postcss](https://github.com/OpenHands/OpenHands/pull/14770)
is on main. So is the sharper fix: a `PluginSpec.source` holding a git token
(`https://oauth2:token@...`) was
[persisted to the database in plaintext](https://github.com/OpenHands/OpenHands/pull/14795)
because the conversation object was serialized whole. New writes are redacted.

**Gemini CLI.** A malicious skill package could write outside `.gemini/skills`
or, through a metadata-driven uninstall fallback, delete sibling directories.
The [fix](https://github.com/google-gemini/gemini-cli/commit/bca5667fc) replaces
prefix checks with real traversal validation.

**Hermes Agent.** Besides the `cp` fix, 13 June commits stop an unauthenticated
`/api/status` from
[leaking host paths and the gateway PID](https://github.com/NousResearch/hermes-agent/commit/3380563d9)
on exposed binds, and make chat adapters such as WhatsApp and WeCom
[fail closed without an allowlist](https://github.com/NousResearch/hermes-agent/commit/fc4635458),
as the project's own security policy already required.

**Paperclip.** In `cloud_tenant` auth mode every tenant on a shared pool was
silently an instance admin, with reach into every other tenant's data. The
[fix](https://github.com/paperclipai/paperclip/pull/7525) removes the grant and
purges stale admin rows. A companion change gives each company its
[own JWT signing key](https://github.com/paperclipai/paperclip/pull/5864) and
cuts token lifetime from 48 hours to one. Both are on master.

**Claude Code.** The OTEL certificate-path fix is in 2.1.169 and the
background-worker fix in 2.1.172.

## Who is left to answer

The fortnight's authority work was not about whether an agent may act. Every one
of these systems already lets it. The work was about who is left to answer when
it asks.

Nine of ten providers narrowed that list, and the direction is consistent:
fewer questions reach a person, more are settled by a rule, and more still by a
classifier reading intent. Each step is defensible. The sequence has a
destination.

Depth forced it. An agent that spawns agents four layers down cannot stop at
every layer to ask, so somebody decides in advance. This fortnight, that
somebody stopped being you.
