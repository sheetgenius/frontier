# The Handoff Has an API

On 13 October, [Oh My Pi (OMP) 18.10.4](https://github.com/can1357/oh-my-pi/releases/tag/v18.10.4) [let an extension revise a plan and answer its execution review while the terminal picker stayed open; the first answer wins](https://github.com/can1357/oh-my-pi/commit/d40b86cf7d6607fc349545ec67ed321023e53425). The person can still be reading when OMP answers. As harnesses take over coding handoffs, operators must choose which ones still wait for a person.

This is a **23-day catch-up issue, covering 21 September through 13 October 2026, inclusive, UTC**. Versions and channels below are as of 13 October 2026, 23:59:59 UTC.

## The planning pause belongs to somebody

On 23 September, Thariq proposed removing Claude Code's plan mode: [[q:trq212-plan-mode-proposal]] A reply from rishi turned the question around:

<!--card:exyota-plan-mode-for-me-->

The next day, Thariq acknowledged [[q:trq212-plan-mode-follow-up]] and proposed preserving the mode as a built-in mod.

Claude's [released changelog still carries plan-mode repairs](https://github.com/anthropics/claude-code/blob/2301018b1f61073c501a8e7a4813ef48c239163b/CHANGELOG.md). Planning can compensate for a model that loses the plot, or give a person somewhere to change the plot. A better model could remove the first need and leave the second intact.

Where a person must choose the plan, restrict OMP extension discovery to reviewed code. OMP [loads project inputs without a trust decision](https://github.com/can1357/oh-my-pi/blob/v18.10.4/README.md#L593-L602).

A plan-only Gemini job needs an enforced write boundary. Gemini [0.63.0](https://github.com/google-gemini/gemini-cli/releases/tag/v0.63.0) [tells headless planning to continue into implementation](https://github.com/google-gemini/gemini-cli/blob/v0.64.0/packages/core/src/prompts/snippets.ts#L602-L615), using [an exit-to-YOLO path already present in 0.62.0](https://github.com/google-gemini/gemini-cli/blob/v0.62.0/packages/core/src/tools/exit-plan-mode.ts#L210-L268). That path leaves planning for execution [without approval prompts](https://github.com/google-gemini/gemini-cli/blob/v0.62.0/packages/core/src/tools/exit-plan-mode.ts#L257-L268).

Claude's [2.1.287 mod launch on 1 October](https://github.com/anthropics/claude-code/releases/tag/v2.1.287) puts more of the harness within reach of plugin code. Claude's launch thread describes installation: [[q:claudedevs-mods-launch]] It also warns about machine access: [[q:claudedevs-mods-machine-access]]

Choosing a Claude mod means choosing who may answer permission questions. An admitted mod [can approve over a rule requiring a prompt or a blocking hook outside managed settings, skipping the model that normally reviews actions in auto mode](https://web.archive.org/web/20261012180805/https://code.claude.com/docs/en/permissions#extend-permissions-with-hooks). [Deny rules take precedence over user-installed mods when the built-in guard loads through managed settings or Team/Enterprise sign-in, with allowModsToOverrideDenyRules false; the mod's own file and process operations remain outside tool rules](https://web.archive.org/web/20261012024958/https://code.claude.com/docs/en/plugins/mods/admin). Additional [controls protecting requests for human approval and policy-related environment variables remain unreleased](https://github.com/anthropics/claude-code/compare/v2.1.296...bf2323b3021c9d3db7a31e1e7d61068c3f704497).

In a root-cause note, Lydia Hallie attributes a reported failure to the order of permission checks: [[q:lydiahallie-hooks-allow-is-approval]]

## Native tools give private adapters less to do

Pi [0.99.0 brought MCP and JavaScript tool composition into the CLI on 29 September](https://github.com/earendil-works/pi/releases/tag/v0.99.0). MCP is [the protocol connecting the agent to external service tools](https://github.com/earendil-works/pi/blob/v1.2.0/packages/coding-agent/docs/mcp.md). Pi's product account announced the reversal: [[q:pidotdev-native-mcp]] On current [1.2.0](https://github.com/earendil-works/pi/releases/tag/v1.2.0), the model can [compose registered tools in a script](https://github.com/earendil-works/pi/blob/v1.2.0/packages/coding-agent/docs/codemode.md). A private bridge whose only job is making those services callable is now a candidate for replacement.

Putting Pi's shell in a VM does not contain every service it starts. Pi [waits for trust before reading project MCP configuration](https://github.com/earendil-works/pi/blob/v1.2.0/packages/coding-agent/src/extensions/mcp/config.ts#L134-L148); its [tool-server subprocesses inherit the harness environment](https://github.com/earendil-works/pi/blob/v1.2.0/packages/mcp/src/transports/stdio.ts#L94). [Putting only shell tools in a VM leaves those servers beside the harness](https://github.com/earendil-works/pi/blob/v1.2.0/packages/coding-agent/docs/security.md#L13-L17). Inspect server configuration and credential scope before running them.

A shorter bridge does not remove the need to control permissions and model spend. Pi's [nested tool calls traverse hooks](https://github.com/earendil-works/pi/blob/v1.2.0/packages/coding-agent/src/core/agent-session.ts#L730-L760), but [scripts can call classification and image-generation models using session credentials outside those individual hooks](https://github.com/earendil-works/pi/blob/v1.2.0/packages/coding-agent/src/extensions/codemode/execute.ts#L499-L751). The [visible tool list also does not fully describe script-callable MCP tools](https://github.com/earendil-works/pi/blob/v1.2.0/packages/coding-agent/docs/cli.md#L111-L138).

Eve lets an existing agent reuse its integrations. Its [optional MCP service lets another harness call eligible tools you define without invoking Eve's model](https://github.com/vercel/eve/blob/eve%400.79.0/docs/channels/mcp.mdx#L216-L346). [Calls run as the authenticated caller, or as a user named by an accepted trusted forwarder](https://github.com/vercel/eve/blob/eve%400.79.0/docs/channels/mcp.mdx#L216-L346). [Calls needing human approval return `approval_required` without running](https://github.com/vercel/eve/blob/eve%400.79.0/docs/channels/mcp.mdx#L216-L346). Pi brings services into its loop; Eve lets an existing loop reach its services.

Kush describes the work the team stopped owning after moving to Eve: [[q:kushbhuwalka-retired-plumbing]] Andrew Barba makes the customization case: [[q:andrew-barba-eve-loop-control]] Eve 0.79.0's [`defaultTools: false` removes framework-default tool definitions while preserving tools explicitly supplied as replacements](https://github.com/vercel/eve/blob/eve%400.79.0/packages/eve/src/compiler/default-tool-policy.ts#L37-L58). Keep customizations your workload still needs.

Shantanu Goel describes batching costs in other implementations: [[q:shantanugoel-batching-dissent]] Mario Zechner poses the minimalist challenge: [[q:badlogicgames-minimal-loop-challenge]] Neither supplies a Pi 1.2.0 comparison; a hundred deleted lines lose their appeal if every batch needs untangling.

Unreal's comparisons do not settle a current-release choice. Its [22 September vendor comparisons report lower input-token use](https://web.archive.org/web/20260922183130/https://unreallabs.ai/blog/unreal-agent/) against historical [Codex](https://hub.harborframework.com/jobs/11a440fb-b1c4-473b-98a6-907500b3fdaf) and [Pi](https://hub.harborframework.com/jobs/6ccd097a-747b-4867-be57-a56969df988f). The build IDs recorded in [Terminal-Bench](https://hub.harborframework.com/jobs/27133053-2015-46f3-8c72-6b6910859da6), [SWE-Atlas](https://hub.harborframework.com/jobs/3d2fa057-e11c-4be0-a962-e8be81b87709) and [DeepSWE](https://hub.harborframework.com/jobs/2311ca63-2929-49eb-ba0c-0084ef31ba8b) are absent from [0.3.1's public commit history](https://github.com/unreallabsai/unreal-agent/commits/55747f5f449c07cf76b3a0747370b5817aa52d5b). Run a [matched current-release trial](/profiles/unreal-agent/) before switching or dismissing its specialized loop ([comparison details](/findings/2026-10-13-profile-refresh-2026-09-21_2026-10-13-frontier-v0/2026-10-13-unreal-agent-the-launch-post-published-benchmark-tables-on-22-september-run-on-builds-absent-from-the/)).

## Consent needs an action, an identity and a moment

Eve [0.78.0 stopped lending the approver's credentials to an approved call and rechecks policy under the requester](https://github.com/vercel/eve/releases/tag/eve%400.78.0). A release manager can consent without silently making their account perform the work.

That credential fix does not fix consent timing. Stable [0.79.0 can still consume requester text queued before its later approval prompt existed](https://github.com/vercel/eve/blob/eve%400.79.0/packages/eve/src/execution/session/input-queue.ts#L229-L244). The [repair excludes those older queued messages and was only on main at cutoff](https://github.com/vercel/eve/commit/0dea0ded869be7db30ae90ed8072d29e6e57df61). An old message cannot answer a question that did not yet exist.

OpenClaw's stable and beta releases protect different parts of approval. On [stable 2026.10.3, an ordinary hook can replace arguments after inline approval](https://github.com/openclaw/openclaw/blob/v2026.10.3/src/agents/agent-tools.before-tool-call.policy.ts#L303-L411). [2026.10.5-beta.3 requires approval for the final replacement parameters or blocks the call](https://github.com/openclaw/openclaw/blob/v2026.10.5-beta.3/src/agents/agent-tools.before-tool-call.policy.ts#L291-L436). Extended-stable [2026.8.35 includes an earlier command-execution approval repair](https://github.com/openclaw/openclaw/compare/ab5611f0be610380fe48803fe4311896ca85806e...v2026.8.35); the hook repair still needs a separate release decision.

Before delegating Eve or OpenClaw approvals, check that the answer follows the request, credentials belong to the requester, and execution uses the approved arguments.

## The running process needs its own owner

Codex package pins no longer necessarily identify the running code. [0.157.0 made eligible interactive terminals clients of a shared background server](https://github.com/openai/codex/releases/tag/rust-v0.157.0). At [0.162.1, eligible npm/Homebrew-seeded servers can update independently](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/app-server-daemon/src/prepare_install.rs#L245-L338) and [retain their startup environment](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/app-server-daemon/README.md#L22-L28). Scrubbing credentials from a new shell does not scrub that server. One account put the inventory problem plainly: [[q:hackerlogs-codex-runtime-inventory]]

Agent Flywheel's [fresh launcher configuration starts interactive Codex](https://github.com/Dicklesworthstone/agentic_coding_flywheel_setup/blob/v0.10.0/install.sh#L9748-L9765); holding its client version does not govern the native server updater. [Explicit standalone pins](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/app-server-daemon/README.md#L104-L139) and [`codex exec`](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/exec/src/lib.rs#L731-L754) have different background-server behavior. Apply this advice to interactive Codex; CI needs its own checks.

Temporal Agent Harness moves waiting into the workflow system. [Preview 0.6.0 moves Monty script stepping into workflow workers](https://github.com/temporal-community/temporal-agent-harness/releases/tag/0.6.0). Scripts [use durable timers and wait for tools or people without holding an interpreter subprocess while they wait](https://github.com/temporal-community/temporal-agent-harness/blob/04a49d1b037de46da2cba31676d2aa2f4c59118f/temporal_agent_harness/harness/code_mode/monty_stepper.py#L9-L106). Jason Steving's design priority is [[q:jasonsteving-durability-first]]

Flue's [released approval recipe takes another route](https://github.com/withastro/flue/blob/v2.3.0/apps/docs/src/content/docs/guide/tools.md#L228-L433): save exact arguments, end the response, then accept a decision through an authenticated application route. Temporal operators check worker and history compatibility; Flue operators supply authentication, expiry and protection against executing the same action twice.

Shiro names a recovery test: [[q:japanaibuilders-resume-side-effects]] Kylian, describing hosted OpenClaw failures, put the dependency plainly:

<!--card:kylian-cros-outside-recovery-owner-->

Name the process or person that can recover the box and reconcile its last external action when the agent itself is down.

## Breaking changes and security notes

**Claude Code graders and CI.** Pin latest 2.1.296 for restricted runs, beyond September's stable recommendation. It includes [2.1.295's repairs for tool restrictions bypassed by late registration of built-ins or deprecated tool names](https://github.com/anthropics/claude-code/releases/tag/v2.1.295).

**Managed Claude Code fleets.** Verify the running account can read its managed policy source. [2.1.285 permits startup after an OS-denied managed-source read](https://github.com/anthropics/claude-code/blob/2301018b1f61073c501a8e7a4813ef48c239163b/CHANGELOG.md#L920).

**Claude Code plugin users.** Verify your release includes [the older 2.1.179 fix named by the 9 October Plugin4Shell advisory](https://github.com/anthropics/claude-code/security/advisories/GHSA-pq7j-f95f-qfcv). It blocks a [requested-commit-pin bypass when installing a malicious plugin from a Git host allowing branch names that look like commit hashes](https://github.com/anthropics/claude-code/security/advisories/GHSA-pq7j-f95f-qfcv). The advisory is new; 2.1.179 is not.

**Claude Code behind gateways.** Record which action checks ran and what they decided on each deployed platform, and alert on the warning notice. Correction to [Before the First Turn](/digests/2026-08-20_2026-09-21-weekly/): we said a gateway stripping the `safeguards` request field makes the first checked action wait on a notice. An unattended run [can print the notice to stderr and continue on billed local checks](https://web.archive.org/web/20260921092459/https://code.claude.com/docs/en/auto-mode-classifier-billing).

**Codex users relying on model review.** Identify the active reviewer and export available review records. Tibo presents Auto-review as an answer to approval fatigue: [[q:thsottiaux-free-auto-review]] At 0.162.1, [the older Guardian reviewer defaults on while Guardian V2 defaults off](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/features/src/lib.rs#L1763-L1814). [Full Access skips model review](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/ext/guardian-reviewer/src/routing.rs#L54-L102). [0.158.0's](https://github.com/openai/codex/releases/tag/rust-v0.158.0) [opt-in export of completed synchronous assessments excludes cached V2 approvals](https://github.com/openai/codex/commit/30758e5c77c14e6ddcc53a6c7407a477fed4ac76), partly answering [The Body, Not the Pencil's auditability question](/features/2026-08-23-codex-the-body-not-the-pencil/).

## Keep the decision, retire the relay

[Bitter Lesson Maxing](/bitter-lesson/) means building where improving general agents compound your advantage. Retire relay code or manual handoffs only when a trial preserves authorization and reduces review time. Keep specialized engineering where recovery and execution requirements still justify its cost.

[Amdahl Maxing](/amdahls-law/) means spending scarce human attention where judgment changes the outcome. Use time saved on routine handoffs to decide who may act, which exceptions deserve escalation and whether work is good enough to accept. The handoff can have an API; deciding what it may authorize still needs an owner.
